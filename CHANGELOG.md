# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Unreleased

## 0.1.9 — 2026-11-27

- `corelata doctor` (and the Settings page's checks) now warns on a `roles` line when the writer and the auditor are the same model, by config key or by the model id a backend serves: a model tends to favour its own drafts when it audits them, so the fix suggests a second model, preferably from another family. It is a warning only; runs work as before. Ticket: CRL-141
- Reasoning models (Qwen3, DeepSeek-R1, gpt-oss) work better: a reply that starts with a `<think>` block now parses without a repair turn, a model's `request_extra` sends server options such as `chat_template_kwargs: { enable_thinking: false }` with every request (the keys Corelata sets itself, `n` and tool calls are refused), `store_reasoning: true` keeps the model's reasoning with each call in `trace.json` (capped by `reasoning_max_chars`, default 20,000; off by default), and `corelata doctor` says on each model's line whether the model reasoned under its structured-output mode. Ticket: CRL-140
- Reviewers can now mark each claim **checked** or **disputed** with a comment on the review screen's Claims tab (`PUT /api/runs/{id}/marks/{claim_id}`, `GET /api/runs/{id}/marks`); the header shows "N of M claims checked" before Accept, every mark is kept with who made it and when in the run's `trace.json` (`review_marks`), and marks are final once the report is accepted. A return hands each disputed claim and its comment to the revision's writer beside the note (with a disputed claim the note may be left empty). Two opt-in profile settings, both off by default: `format.production_statement: true` ends the Markdown, HTML and Word renders with "How this report was produced" (the models each role used, the standards pack and its hash, the audit result and "N of M claims checked by <reviewer>"), and `review.require_key_judgments_checked: true` makes Accept wait until every claim a key judgment rests on is checked and none is disputed. Migration 0012 adds the marks table. Ticket: CRL-139
- `HEAD /api/health` and `HEAD` on the web app (`/`, its pages and static files) now answer 200 with no body instead of 405, so uptime monitors, load balancers and `curl -I` see Corelata as up; the OpenAPI document is unchanged. Ticket: CRL-116
- An analyst can now state what they know about a source (its descriptor, reliability note, date of information, origin and access) when uploading it or later, from the new report page's **Details**, `PATCH /api/projects/{id}/sources/{sid}`, upload form fields, `corelata ingest --origin ...` or `corelata source set`. Stated values are checked against the standards pack's lexicon and go into the report verbatim in place of what the model inferred; the trace records each value the engine overwrote and the review screen's Sources tab labels every value "stated by analyst" or "inferred by model". A run keeps the values it was queued with, and a source with nothing stated behaves exactly as before. Ticket: CRL-138
- The new-report form now has a "Guidance for the writer" box under More options (up to 8,000 characters, with a count near the limit), kept with the rest of the draft; "start from an earlier run" fills it from that run, and the report's progress page shows the guidance the writer was given. `GET /api/runs/{id}` (and the run events) gain `extra_guidance`, which is empty for a run started without guidance. Ticket: CRL-132
- Accept on the review screen now asks first: a dialog says the decision is final (the report can't be returned afterwards and will be used as project memory); Cancel records nothing and returns to the Accept button, and confirming moves focus to the banner that states the decision. Ticket: CRL-127
- The README now starts with what Corelata is, a screenshot, the requirements and a three-command quick start (`make demo`); the milestone notes moved to `docs/history.md`. `make demo` now works from a fresh clone: it copies the base standards pack into `deploy/config/packs/` when that directory is missing. Ticket: CRL-133
- Operators can now remove a source uploaded by mistake, or a whole project, from the command line: `corelata sources --project NAME` lists a project's sources with their ids, `corelata delete-source ID` deletes a source with its stored file (refused while runs used it, unless `--with-runs` deletes those runs too), and `corelata delete-project NAME` deletes a project and everything in it. Both list what they delete and ask to confirm (`--yes` for scripts), refuse while a run they would delete is still queued or writing, and log one audit line (operator guide, "Removing a source or a project"). Ticket: CRL-125
- The job queue runs on procrastinate 3.12.0 (from 3.10.0): migration 0011 applies procrastinate's 3.11 and 3.12 schema migrations, and jobs already queued are kept. A stalled job whose copy is already waiting is now closed by procrastinate itself when the worker re-queues it. Upgrade by stopping the old version first, as the operator guide's upgrade steps already do.
- Corelata can now check a finished report someone else wrote against the standards pack without rewriting it: `corelata check report.docx sources/... --pack ...` (exit 0 when every standard is met, 3 when not) or `POST /api/runs` with `kind: check` and the uploaded report's `report_source_id`. Every sentence of the report becomes a claim word for word, a sentence no source supports fails the sourcing standards, and the result comes with a findings sheet (`findings.csv`); the review screen shows the checked report without Accept or Return. Ticket: CRL-94
- Source text can no longer quietly steer a report: every prompt that reads sources now says their text is data, never instructions (new prompt versions `gate/v2`, `discover/v2`, `digest/v2`, `writer/v6`, `auditor/v6`); text an HTML or DOCX file hides from its reader is kept in the trace but sent to no model; passages that read as instructions to an AI are flagged `suspect` for the models, which must not rest a claim on them (the auditor fails `icd203.tc.8` for one that does), and the review screen's Sources tab and `corelata trace` count both; the `real` bench set adds a visible and a hidden injection scenario. Ticket: CRL-137
- The engine now checks likelihood and confidence wording against ICD 203 itself, not only through the model: a key judgment or judgment claim that states a confidence level and a likelihood in one sentence, uses a word from another row of the likelihood table or none ("probably", "perhaps"), or does not use its own likelihood term fails `icd203.tc.2` and goes back to the writer, even when the audit is incomplete. Base pack 1.2.0 adds the three word lists to its lexicon; a pack without them behaves as before, and a profile can relax the check by disabling or downgrading the rule. Ticket: CRL-136
- The public site lives at https://corelata.tech: its canonical, Open Graph and structured-data URLs, sitemap, robots file, `security.txt`, page text and site check use the new host, and corelata.com redirects there. Ticket: CRL-143
- No other site can show Corelata in a frame (`X-Frame-Options: SAMEORIGIN`; an HTML report: `DENY`), and every API answer except the health check carries `Cache-Control: no-store`, so report and source text is not kept in a shared workstation's browser cache. Ticket: CRL-131
- Below 440 CSS px wide (400% zoom, or a phone held upright) the top bar now wraps onto extra lines and scrolls away with the page instead of clipping "Your projects" and covering the page, and the projects sidebar opens just below it (WCAG 1.4.10 Reflow). Ticket: CRL-129
- A link to a report or project that no longer exists, or a link cut short, now shows "Report not found" or "Project not found" with a way to start a report or choose a project, and the browser tab says so, instead of a bare error line or an empty project form; other errors still show as before. Ticket: CRL-130
- A request whose text holds an unpaired UTF-16 surrogate (as pasted from a broken export) now answers 422 naming the field instead of 500, and validation answers no longer echo the submitted input. Ticket: CRL-128
- Pack loading, reference-document reads, the web app's file lookups and the doctor's config, prompt and pack checks run off the event loop, so a slow packs directory no longer stalls other requests. Ticket: CRL-113
- An unreachable Coglossa and an unknown pack no longer reveal server addresses or paths to the client (the log keeps them); a Coglossa error answer is read only to 64 KB, and an import is held to the upload limit. Ticket: CRL-114
- Releases publish only from a tag on main, build and test with a read-only token, and ship a Postgres image pinned by digest (recorded in the bundle manifest); every CI job has a timeout. Ticket: CRL-115
- `GET /api/system/doctor` no longer sends test completions unless asked: an API caller that wants them now passes `probe=true`. Concurrent or repeated probes within 30 s share one run. Ticket: CRL-112
- Opening a claim's provenance or a run's trace no longer stalls the server while a large source is read: a claim read fetches only the passages it cites, the trace counts each source's passages in the database, and loading a whole source happens off the event loop. Ticket: CRL-124
- Uploading a file, or importing a Coglossa run, that the project already has no longer adds a second copy: the API answers 200 with the existing source, flagged `already_in_project`, and the upload chip says "already in this project". Ticket: CRL-126
