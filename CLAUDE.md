# CLAUDE.md

Guidance for Claude Code sessions working in this repository.

## What Corelata is

Standards-enforced intelligence report production with a full trace. An analyst supplies source
material and a statement of its intelligence value; the pipeline gates the statement against the
sources, drafts an ICD 203-shaped assessment, reviews it for the reader, audits it rule by rule
against a replaceable standards pack, and delivers the report with every claim linked to its
evidence. The report is always delivered: a stage that has something to deliver degrades, a stage
that has nothing (gate, writer) fails.

The first customer is air-gapped and brings their own OpenAI-compatible model servers. There is no
customer corpus; ICD 203 + ICD 206 ship as the base pack and the customer tunes or replaces it.

- Spec: `docs/superpowers/specs/2026-10-12-corelata-v1-design.md` (the authority; plans argue from it)
- Plans: `docs/superpowers/plans/` (one per milestone); follow-ups: `docs/m<N>-followups.md` (ticket keys: `docs/followups.md`)
- Operator guide: `docs/operator-guide.md`; trace format: `docs/trace-format.md`
- Jira project `CRL`; Confluence record under `OPS > Projects > Corelata`

## Layout

| Directory | Contents |
| --- | --- |
| `engine/` | the `corelata` Python package (uv): config, llm, prompts, standards, ingest, stages, pipeline, schema, render, store, worker, bench, profiler, CLI, synthetic test model |
| `api/` | `corelata_api` (FastAPI, uv; editable dependency on `../engine`) |
| `web/` | the review UI (Vite, React 19, TypeScript, pnpm 10, Node 22); client types generated from `schema/openapi.json` |
| `deploy/` | Dockerfile, Compose stacks, install/backup/restore/bundle scripts, air-gap tests; `deploy/hosted/` is the optional hosted demo (`deploy/hosted/README.md`) |
| `schema/` | exported JSON schemas and `openapi.json`, regenerated by `make schema` and committed |
| `docs/` | spec, plans, operator guide, trace format, per-milestone follow-ups |

## Commands

Verify: `make lint && make -o db-up test` against a Postgres superuser at `CORELATA_TEST_DATABASE_URL` (`make db-up` first locally; `-o db-up` skips Docker where Postgres runs natively, as in cloud sessions).

```bash
make db-up                 # Postgres 16 in Docker on 127.0.0.1:55433 (deploy/compose.dev.yaml)
make lint                  # ruff check + format --check (engine, api); eslint, prettier, tsc (web)
make test                  # test-engine, test-api (pytest with the dev database), test-web (vitest)
make e2e                   # Playwright against api/devstack.py
make schema                # regenerate schema/*.json, schema/openapi.json, web/src/api/schema.d.ts
make deploy-check          # shell and compose checks under deploy/
cd deploy/hosted/vercel && pnpm install && pnpm typecheck && pnpm test   # hosted-web
# hosted-modal: the command in deploy/hosted/README.md § Checks and operations
make airgap-test           # build the image and install the bundle on a sealed network (~15 min)
cd engine && uv run corelata --help
cd engine && uv run corelata fake-openai   # synthetic model on 127.0.0.1:8000 for smoke tests
```

Tests that touch Postgres read `CORELATA_TEST_DATABASE_URL`
(`postgresql://corelata:corelata@127.0.0.1:55433/postgres`; the make targets set it). A single
file: `cd engine && CORELATA_TEST_DATABASE_URL=... uv run pytest tests/x.py --no-cov -q`. Do not run
the full pytest and Vitest suites concurrently; both are timing-sensitive.

## Gates

- CI jobs (`ci.yml`, on every pull request and every push to `main`) `engine`, `api`, `web`, `e2e`,
  `deploy`, `hosted-web` and `hosted-modal` (the hosted demo, `deploy/hosted/`), `airgap` (pull
  requests only) and the aggregate `ci-status`, which branch protection requires. Runners are
  pinned to `ubuntu-24.04`, except `web` and `ci-status`, which run on `vars.RUNS_ON` when it is set
  and the pull request is not from a fork (`deploy/tests/check_workflows.py`).
- Branch coverage gate 95% for `engine` and `api` (`--cov-fail-under=95`); `filterwarnings = ["error"]`.
- Vitest thresholds 95% on lines, branches, functions and statements.
- `make schema` must leave `schema/` and `web/src/api/schema.d.ts` unchanged unless the change is
  deliberate and committed with the code; `test_committed_schema_matches_models` and the `web` job
  enforce it. No new API route without updating `api/tests/test_openapi.py::test_every_screen_has_its_routes`.
- The synthetic model cannot produce a real server's failures. Before a release, run
  `corelata doctor` and `corelata bench --scenarios real` against an OpenAI-family provider as well
  as a local server and post the numbers on the ticket.

## Conventions

- Work in a worktree under `.claude/worktrees/<branch>`; one branch per plan or fix; squash-merge
  pull requests and delete the remote branch. Merge your own PR only when all CI checks are green.
- Milestones run as a plan PR (`docs/superpowers/plans/YYYY-MM-DD-<name>.md`, written against the
  spec with explicit rulings `R-M<N>-<k>`) followed by an implementation PR; subagent-driven
  development with a task review per task and a whole-branch review before the PR. Rulings made
  during execution and anything deferred go into `docs/m<N>-followups.md`.
- Constraints a model must obey belong in the per-call JSON schema first and in a validator
  second; the stage parses with the canonical type so one repair message carries every error.
  Every schema stays inside the strict subset (`llm/schema.strict_json_schema`). Every model request
  goes through `llm/agent.request_messages` and `build_request`, so `corelata doctor` sends what a run
  sends.
- Anything the API serves is generated into `schema/openapi.json` and the web client together.
  Anything that walks the filesystem or parses on a request path runs in `asyncio.to_thread`.
- The version lives in `engine/pyproject.toml`, `api/pyproject.toml`, `web/package.json`, both
  `uv.lock` files, `engine/corelata/__init__.py` and `schema/openapi.json`; bump, then `uv lock`,
  `uv sync` and `make schema`. A `v<version>` tag on main publishes the bundle.
- Commit messages: conventional prefix (`feat:`, `fix:`, `docs:`, `chore:`), the Jira key in the
  subject when there is one, and the attribution trailers the session is given.
- Never commit `deploy/.env`, `deploy/config/corelata.yaml` or any model-server key; the OpenRouter
  key for rehearsals lives outside the repo in `~/.config/corelata/openrouter.env`.
